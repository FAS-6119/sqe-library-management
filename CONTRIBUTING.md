# Contributing Guidelines

## Branching Strategy

We use a feature-branch workflow.

- `main` — stable and releasable code
- `feature/<slug>` — new features
- `fix/<slug>` — bug fixes
- `docs/<slug>` — documentation changes

## Pull Requests

All changes should be made through a Pull Request.

Before merging:
- Code should be reviewed.
- Tests should be added or updated where needed.
- Documentation should be updated where needed.
- Related issues should be linked.
